# Тип API для взаимодействия микросервисов и обоснование выбора

---

#### 1. Auth Service (Сервис авторизации)
**Тип API:** REST API  
**Обоснование:**  
- REST подходит для синхронных запросов, таких как авторизация и проверка токенов, где требуется немедленный ответ клиенту (успех/неуспех).  
- Примеры:
  - Вход пользователя.
  - Проверка валидности токена.

---

#### 2. Device Management Service (Сервис управления устройствами)
**Тип API:** REST API  
**Обоснование:**  
- REST используется для управления устройствами (добавление, удаление, изменение состояния). Это критически важно для операций, где пользователю нужно немедленное подтверждение (например, включение света).  
- Примеры:
  - Включение/выключение устройства.
  - Настройка сценариев управления устройствами.

---

#### 3. Telemetry Service (Сервис телеметрии)
**Тип API:**  
- **REST API** для запросов телеметрических данных (например, получение истории измерений).  
- **AsyncAPI (Kafka)** для асинхронной отправки данных телеметрии.  

**Обоснование:**  
- REST удобен для получения исторических данных или данных в реальном времени по запросу.  
- Kafka используется для передачи телеметрии от устройств к микросервисам, чтобы снизить нагрузку на систему и обрабатывать большие объемы данных асинхронно.

---

#### 4. Notification Service (Сервис уведомлений)
**Тип API:**  
- **REST API** для управления шаблонами уведомлений и настройки предпочтений пользователей.  
- **AsyncAPI (Kafka)** для отправки уведомлений.  

**Обоснование:**  
- REST позволяет пользователю синхронно управлять настройками уведомлений.  
- Kafka используется для обработки событий в реальном времени, чтобы уведомления доставлялись быстро и без задержек.

---

#### 5. Integration Service (Сервис интеграции с устройствами)
**Тип API:** REST API  
**Обоснование:**  
- REST подходит для управления конфигурацией интеграции (например, настройка устройства ZigBee). Здесь важен немедленный результат для пользователя.  
- Прямое взаимодействие с устройствами через протоколы (ZigBee, MQTT) осуществляется внутри сервиса и не требует внешнего асинхронного API.

---

#### Итоговое обоснование

- **REST API** используется для запросов, требующих немедленного отклика и удобной интеграции с клиентскими приложениями (например, пользовательские операции или управление устройствами).  
- **AsyncAPI** на базе Kafka применяется там, где важна высокая производительность, масштабируемость и асинхронная обработка (например, телеметрия и уведомления).  

Такой подход обеспечивает баланс между удобством разработки, производительностью и отказоустойчивостью.
